# 音声コマンドと書き取る言葉を、既存の製品はどう見分けているか

調べた日: 2026-11-08。出典は公式のヘルプを優先し、公式に書かれていないものは「非公式」と断った。

## 結論

既存の製品の見分け方は、次の4つの組み合わせである。

1. **前後の間**。Dragon が一番はっきり書いている。間を置いて言った短い句だけをコマンドの候補にし、続けて話した中の同じ言葉は文字にする。Google（Pixel の高度な音声入力）と Apple（Voice Control）も、公式の目安は **0.5 秒**。Windows の音声アクセスの「動作するまでの待機時間」の既定も 0.5 秒（非公式の資料による）。Dragon の古い既定は 0.25 秒だった。
2. **区切り全体の一致**。区切った中にコマンドの言葉が「含まれる」だけでは発動させない。Aqua Voice は、発話の全体を読んで、コマンドが**最後に言ったものであるとき**だけ送信する。
3. **モード**。Apple・Dragon・Windows の音声アクセス・Talon は、コマンドだけ・書き取りだけのモードに切り替えられる。Wispr Flow と Aqua の編集は、別のキーを押している間だけコマンドとして聞く。
4. **逃げ道**。Windows の音声アクセスは「Type ＜コマンド＞」で、コマンドの言葉をそのまま文字にする。Android の Voice Access も「Type ＜語句＞」を持つ。Pixel は逃げ道を公式に書いておらず、誤爆したら「元に戻す」で戻す作りである。

Kanade の既定値の提案（理由は最後の章）:

| 項目 | 提案 |
|---|---|
| 前の間 | **600 ms 以上**の無音。録音の始めは間があるものとみなす |
| 後ろの間 | **600 ms 以上**の無音。録音の終わり（キーを離す）は間があるものとみなす |
| 区切りの長さの上限 | 話している部分が **2.0 秒以下**、かつ読みで **16 文字以下** |
| 区切りの長さの下限 | 話している部分が 250 ms 以上（短すぎる区切りは幻聴を拾いやすい） |
| 一致の甘さ | **区切りの全体が、決めた言い方の一覧のどれかに一致したとき**だけ。句読点・空白・丁寧な語尾（「ください」「お願い」）を落としてから比べる。ゆらぎは一覧に書き足して吸収し、編集距離であいまいに比べることはしない |
| 位置 | 「送信して」「止めて」は**録音の最後の区切り**のときだけ。「削除して」などの直しは途中でもよい |
| 逃げ道 | 「〜とにゅうりょく」のような前置き、コマンドを切る設定、発動した直後に元へ戻す操作 |

## 製品ごとの決まり

### Dragon（NaturallySpeaking / Professional）

Dragon は、間の長さでコマンドか書き取りかを決めると公式に書いている。

- 「Dragon は2つの発話の間の長さで、コマンドを言っているか書き取りかを決める」。その長さは「オプションのダイアログのコマンドのページ」で変えられる ([Nuance: If commands are being recognized as dictation](https://www.nuance.com/products/help/dragon/dmpe42/enx/dmpe/Content/tshoot/commands_entered_as_text.htm))。
- Mac 版の説明はさらに具体的である。「コマンドは途切れずに滑らかに言い、その前と後ろで間を置く」「続けて話すと、コマンドになりうる言葉が入っていても書き取りとして扱う」「句の前後で間を置くと、その句をコマンドの候補とみなす」 ([Nuance: Recognition Modes（Dragon for Mac 6）](https://www.nuance.com/products/help/dragon/dragon-for-mac6/enx/Content/Introduction/RecognitionModes.html))。句読点についても「前と後ろで少し間を置く」と書いている ([Nuance: Getting started with dictation](https://www.nuance.com/products/help/dragon/dragon-for-mac6/enx/Content/Dictating/Getting_started_with_dictation.htm))。Dragon Home 15 の手引きも「コマンドの前後で間を置き、コマンドの途中では置かない」 ([Dragon Home 15 Quick Start Guide（PDF）](https://www.nuance.com/asset/en_us/collateral/dragon/guide/gd-dragon-home-v15-quick-start-guide-en-us.pdf))。
- **秒数**: Dragon NaturallySpeaking 6・7 の頃のユーザーガイドに「Pause required before commands（コマンドの前に要る間）」という設定があり、**既定は 250 ミリ秒（0.25 秒）**、「普通は既定のままにする」とある ([Dragon NaturallySpeaking 7 User's Guide の写し（manualsdir）](https://www.manualsdir.com/manuals/441252/sony-icd-ms515vtp.html?page=175))。今の版の既定値は公式のヘルプに見つからなかった。利用者の掲示板では「既定は約 0.5 秒」と答えている ([Tom's Guide Forum](https://forums.tomsguide.com/threads/dragon-naturallyspeaking-12-0-types-%E2%80%98scratch-that%E2%80%99-instead-of-erasing-last-spoken-phrase.341793/latest)。非公式)。
- **例外**: 「Cap」「New Line」のような書き取りの中で使うコマンドは、前に間を置かない。「Select ＜語＞」「Insert Before ＜語＞」は、コマンドの言葉と対象の語の間で間を置かない ([Nuance](https://www.nuance.com/products/help/dragon/dmpe42/enx/dmpe/Content/tshoot/commands_entered_as_text.htm))。間が要るのは句の外側だけで、句の中の間は区切りを壊す。
- **強制する手段**: 「Ctrl キーを押しながら言うと、書き取りを止めて、言ったことをコマンドとして認識させる」 ([Nuance](https://www.nuance.com/products/help/dragon/dmpe42/enx/dmpe/Content/tshoot/commands_entered_as_text.htm))。
- **モード**: 普通（書き取りとコマンド）・書き取り・コマンド・数字・つづりの5つ。「Start Command Mode」などと言うか、メニューで切り替える ([Nuance: Using recognition modes（Dragon 15）](https://www.nuance.com/products/help/dragon15/dragon-for-pc/enx/dpg-vla/Content/DragonBar/dragonbar_recognition_modes.htm))。コマンドモードで「コマンドと解釈できないことを言うと、何も起きない」 ([Nuance（Mac 6）](https://www.nuance.com/products/help/dragon/dragon-for-mac6/enx/Content/Introduction/RecognitionModes.html))。
- **誤爆の向き**: Dragon でよく出る不満は、逆向きの「コマンドが文字として入る」である。「Scratch That と言うと、消えずにその文字が入る」という相談に、普通モードに戻す・文とコマンドの間に間を置く、と答えている ([Tom's Guide Forum](https://forums.tomsguide.com/threads/dragon-naturallyspeaking-12-0-types-%E2%80%98scratch-that%E2%80%99-instead-of-erasing-last-spoken-phrase.341793/latest))。公式のトラブル対処も同じ向きで、間の長さを変える・Ctrl を押す・よく間違えるコマンドを学習させる、を挙げる ([Nuance](https://www.nuance.com/products/help/dragon/dmpe42/enx/dmpe/Content/tshoot/commands_entered_as_text.htm))。間を条件にすると、コマンドが文字になる取りこぼしの方が、文字がコマンドになる誤爆より起きやすい。
- MouseGrid は画面を9つに割って番号で指すコマンドで、見分け方の話には関係しないので深追いしなかった。

### Google Pixel の高度な音声入力（Gboard）

- コマンドの一覧: 送信「Send」、止める「Stop」、最後の文を消す「Clear」、全部消す「Clear all」、最後の単語を消す「Delete last word」、次の欄へ「Next」 ([Gboard ヘルプ（英語）](https://support.google.com/gboard/answer/11197787?hl=en))。日本語のヘルプでの言い方は **「送信して」「止めて」「すべて消去して」「最後の単語を削除して」「次へ」**、詳細な編集の全消去は「すべてクリア」 ([Gboard ヘルプ（日本語）](https://support.google.com/gboard/answer/11197787?hl=ja))。高度な音声入力は Pixel 6 以降で、日本語を含む6言語に対応する。
- **秒数**: 詳細な編集のコマンドは「少し間を置いて（**0.5 秒以上**）」から言う。日本語のヘルプの例は「エミリー、ジェシカ、ジェニーを夕食に招待しました。（一時停止）エミリーの後にアンナを挿入して。」 ([Gboard ヘルプ（日本語）](https://support.google.com/gboard/answer/11197787?hl=ja))。ただし詳細な編集は英語（米国）と Pixel 8 以降だけで、日本語では使えない。「送信して」などの基本のコマンドに間の決まりは書かれていない。発表のころの記事は「文字が入ってから（間を置いて）Send と言うと送られる」と書いている ([9to5Google](https://9to5google.com/2021/10/19/pixel-6-gboard-assistant-voice-typing/))。
- **逃げ道**: 「send」「stop」をそのまま文字にする方法は、公式のヘルプにも記事にも見つからなかった。誤爆の後に「Undo（元に戻す）」で戻す作りで、記事は「うっかり消してしまった発話も含めて、直前の操作を戻す」と書いている ([Computerworld](https://www.computerworld.com/article/4026831/android-voice-typing.html))。同じ記事は「send の一語で、声で作った文がすぐに送られる。賢く使うこと」と注意している。コマンドを切る設定も見つからなかった。

### Apple（Voice Control と iPhone の音声入力）

- **Voice Control のモード**: 音声入力モード（既定）は「コマンドでない言葉を文字として入れる」。コマンドモードは「コマンドにだけ応え」、ほかの言葉は捨てる。スペルモードは1文字ずつ ([Apple: Mac で音声コントロールのコマンドを使う](https://support.apple.com/guide/mac-help/use-voice-control-commands-mh40719/26/mac))。
- **秒数**: 「コマンドを素早く続けて言うときは、コマンドの間で**約 0.5 秒**一時停止する」 ([Apple（日本語）](https://support.apple.com/ja-jp/guide/mac-help/mh40719/mac))。書き取りとコマンドの間の決まりではなく、コマンドどうしの区切りの目安である。
- **逃げ道**: 公式の答えは「誤って音声コントロールのコマンドがテキストとして入力されないようにするには、コマンドモードで、音声コントロールをコマンドにのみ応答させる」 ([Apple（日本語）](https://support.apple.com/ja-jp/guide/mac-help/mh40719/mac))。逆向きの「コマンドの言葉を文字として入れる」前置きは見つからなかった。コマンドは1つずつ切ったり、自分で作ったりできる ([Apple: Voice Control のコマンドをカスタマイズする](https://support.apple.com/en-ng/118275))。音声コントロールは日本語に対応している（同じページの対応言語の一覧）。
- **iPhone のキーボードの音声入力**: 句読点・書式・改行のコマンドは日本語にもある。「〜を削除」「すべて削除」「取り消す」などの編集のコマンドは、**iPhone 12 以降の米国英語だけ**である ([Apple: iPhone でテキストの音声入力に使えるコマンド](https://support.apple.com/ja-jp/guide/iphone/iph3bf19d7b9/ios))。送信のコマンドはない（Siri で送る形）。

### Windows（音声アクセスと Win+H の音声入力）

- **音声アクセスのモード**: 「Dictation mode（書き取りだけ）」「Commands mode（コマンドだけ）」「Default mode（コマンドと書き取り）」を声で切り替える ([Microsoft: 音声アクセスのコマンド一覧](https://support.microsoft.com/en-us/topic/voice-access-command-list-dac0f091-87ce-454d-8d57-bef38d3d8563))。
- **逃げ道**: 「Type ＜コマンド＞」または「Dictate ＜コマンド＞」で、コマンドを実行せずに文字として入れる。例は「Type What can I say」 ([Microsoft: 声でテキストを書き取る](https://support.microsoft.com/en-US/Accessibility/windows/voice-access/dictate-text-with-voice))。調べた中で、コマンドの言葉を書き取る前置きを公式に持つのはこれと Android の Voice Access だけである。
- **秒数**: 音声アクセスの設定に「動作するまでの待機時間（Wait time before acting）」があり、「設定した時間待ってから、コマンドや入力を処理し始める」 ([Microsoft: 音声アクセスの更新履歴](https://support.microsoft.com/en-US/accessibility/windows/voice-access/history-of-voice-access-updates))。公式は値を書いていない。第三者の解説は、Instant 0.1 秒・Very Short 0.2 秒・Short 0.3 秒・**Medium 0.5 秒（既定）**・Long 1.0 秒・Extended 2.0 秒・Very Long 3.0 秒の7段とする ([ElevenForum](https://www.elevenforum.com/t/change-voice-access-wait-time-before-acting-in-windows-11.40439/latest)。非公式)。音声アクセスは日本語に対応した（同じ更新履歴）。
- **Win+H の音声入力**: 「それを削除」「それを選択」「音声入力を停止」や Enter・BackSpace などのキーのコマンドがあり、日本語の一覧もある。新しい版には同じ名前の「動作するまでの待機時間」がある ([Microsoft: 音声入力を使用して PC で話す代わりに入力する](https://support.microsoft.com/ja-jp/windows/use-voice-typing-to-talk-instead-of-type-on-your-pc-fec94565-c4bd-329d-e59a-af033fa5689f))。コマンドを「それを削除」のように、文の中では言わない形にしているのも見分ける工夫とみられる（公式の説明はない）。

### Talon Voice

- 既定はコマンドモードで、言ったことを決まった語彙に当てはめる。そのまま書き取るには書き取りモードに入るか、「say ＜句＞」「sentence ＜句＞」で一時的に書き取る ([fileside の体験記](https://www.fileside.app/blog/2025-04-14_voice-computing/))。
- **秒数**: `speech.timeout` は「話し終えたと決めて、言ったことをコマンドの列として解釈するまでに待つ間」で、**既定は 0.300 秒** ([Talon Community Wiki: Settings](https://talon-wiki-refactor.netlify.app/Basic%20Usage/settings))。Talon 0.1.5 で 150 ms から 300 ms に上げた ([Talon 0.1.5 の更新](https://talonvoice.com/update/pgUuEYK3vzmYQtF2PMgOyK/Talon-108-0.1.5.html))。体験記の作者は 0.5 秒に上げ、「say」の書き取りが短い間で切れて、続きがコマンドとして実行されると書いている。
- **誤爆**: 同じ体験記は「一番の悩みは、コマンドの取り違え」「文脈のない短い語の認識は、今の音声認識にもまだ難しい」と書く。短い一語のコマンドは誤認識に弱い。

### Wispr Flow

- Command Mode は**別のキーを押している間**だけ。Mac は Fn+Ctrl、Windows は Ctrl+Win+Alt を押しながら指示を言い、離すと実行する。500 ms 以内に2回押すと押さずに続けられる。既定でオフ ([Wispr Flow: How to use Command Mode](https://docs.wisprflow.ai/articles/4816967992-how-to-use-command-mode))。
- 「デスクトップでは、普通の書き取りの中で "Hey Flow" や "ask perplexity" と言っても Command Mode は始まらない」「声の合図は英語だけ、キーでの起動はどの言語でも使える」（同じページ）。書き取りの中の言葉からコマンドを拾うことを、わざとしていない。

### Aqua Voice

- 「Send It」: Realtime Mode の書き取りを「send it」で終えると、その言葉を文から抜いて入れ、送信のキーを押す。
- **見分け方**: 「キーワードを当てるのではなく発話の全体を読むので、コマンドは**最後に言ったもの**でなければならない」。「Running late, be there soon, send it」は送り、「Tell them I'll send it tomorrow」は文字のまま。言い方は決まっておらず「send」「please send this message」も通る ([Aqua Voice: llms.txt](https://aquavoice.com/llms.txt))。
- **日本語**: 「送って」「送信してください」のような自然な言い方が通る（同じページ）。
- Edit Mode は、文字を選んでキーを押しながら直したい形を言う。コマンドの言葉は要らない ([Aqua Voice: Edit Mode](https://aquavoice.com/edit-mode))。送信のキーを「Paste Only（入れるだけで送らない）」にもできる。

### Android の Voice Access

- 入力欄では言った言葉がそのまま入り、「Type ＜語句＞」でも入れられる。「Stop editing」は「次のコマンドが文字の入力と解釈されないように編集をやめる」 ([Google: Voice Access のコマンド](https://support.google.com/accessibility/android/answer/6151854))。
- 日本語に対応するが、「ポルトガル語と日本語は、よく使う 25 のコマンドだけ」（同じページ）。間の秒数は書かれていない。

## 日本語のコマンドの言い方

| 操作 | Pixel（公式） | Windows Win+H（公式） | Aqua（公式） |
|---|---|---|---|
| 送信 | 送信して | （Enter を押す） | 送って・送信してください |
| 止める | 止めて | 音声入力を停止 | — |
| 消す | すべて消去して・最後の単語を削除して | それを削除・それを消去 | — |
| 次の欄 | 次へ | （Tab を押す） | — |

Pixel は「〜して」の依頼の形、Windows は「それを〜」の指す形である。日本語の文末の「〜して」は普通の文にもよく出る（「資料を送信して」）。区切りの全体で比べないと、「送信して」で終わる文を送ってしまう。

## Kanade で作るときの既定値と注意点

前提: Kanade には聞き続けるモードがあり（`SPEC.md` 8-3）、`VoiceEndpointer` は 700 ms 黙ると区切る（話し始めは 150 ms、上限 20 秒）。ここでの「区切り」は、1回の録音の中で無音に挟まれた話し声のひとかたまりを指す。

### 間の長さ: 前後とも 600 ms

- 公式の目安は Google・Apple・Windows（非公式の既定）がそろって 0.5 秒、Dragon の古い既定が 0.25 秒、Talon が 0.3 秒。0.25〜0.3 秒は Dragon と Talon のようにコマンドを打つ人向けの値で、普通に話す人には短すぎる。Talon の体験記も 0.5 秒に上げている。
- 日本語は文中の息継ぎ（読点の位置）で 0.3〜0.5 秒ほど間が空く。0.5 秒ちょうどだと、「…ので、（間）送信して」と文の一部として言った「送信して」を区切ってしまう。少しだけ長い **600 ms** を提案する。今の区切り（700 ms）より短くしておくと、聞き続けるモードで区切りが閉じる前にコマンドかどうかを決められる。
- 音の大きさで無音を測ると、語尾の減衰で無音の始まりが遅れて測られる。600 ms は「音が閾値を下回ってから」の長さとして測る。
- 録音の始め（キーを押した直後）と終わり（キーを離した）は間があるものとみなす。押して「送信して」とだけ言って離すと、送信になる。

### 区切りの長さ: 2.0 秒以下、読みで 16 文字以下、250 ms 以上

- 一番長い候補の「さいごのたんごをさくじょして」が 14 文字で、普通の速さで約 1.8 秒。上限はこれが入る 2.0 秒・16 文字にする。これより長い区切りは文とみなし、比べもしない。
- 短すぎる区切り（250 ms 未満）は、咳や「えっと」を認識モデルが短い語に聞き違えやすい。8-5 の幻聴の除外と同じ理由で捨てる。

### 一致の甘さ: 区切り全体の一致、ゆらぎは一覧で

- 区切りの文字から句読点・空白・「。」「、」を落とし、丁寧な語尾（「ください」「下さい」「お願い」「お願いします」）を落としてから、言い方の一覧と**完全に一致**するかで決める。「含む」で決めない（Aqua の「最後に言ったもの」、Dragon の「句全体がコマンド」と同じ考え）。
- 認識の表記ゆれ（「送信して」「そうしんして」「送信、して」）は、読み（かな）にそろえてから比べれば大半が吸収できる。編集距離での比べ方は、「返信して」「送金して」「消して」のような近い語を拾うので使わない。足りないゆらぎは一覧に書き足す。
- 区切りの文字は、確定用のモデルが録音の全体をまとめて出した文からではなく、区切りの音声だけを認識した結果か、時刻の付いた結果から取る。まとめて認識させると、前の文とつながって「〜です送信して」のように出て、区切りが分からなくなる。

### 位置: 送信と停止は最後の区切りだけ

- 「送信して」は取り消せない。**録音の最後の区切り**であるときだけ送る（Aqua と同じ）。途中で言った「送信して」は文字のままにする。止めて（「止めて」）も同じく最後だけにする。
- 「最後の単語を削除して」「すべて消去して」のような直しは途中でもよいが、直前の操作を戻せるようにする（Pixel の「元に戻す」）。消した文字は、戻せるうちは捨てない。

### 逃げ道と誤爆の対処

- **コマンドを切る設定**を置き、送信は既定でオフにすることも考える（取り消せない操作は、誤爆の害が一番大きい）。Apple のように1つずつ切れるとよい。
- **書き取る前置き**: Windows の「Type ＜コマンド＞」にならい、「〜とにゅうりょく」「にゅうりょく ＜語＞」でコマンドの言葉を文字にする。続けて話せば文字になるので、ほとんどの場合は前置きは要らない。前置きが要るのは「送信して」だけを書き取りたいときくらいである。
- **発動したことを見せる**: 何のコマンドとして受け取ったかを短く表示し、その場で戻せるようにする。Pixel は誤爆の対処を「元に戻す」に任せており、Kanade も同じ形が一番安い。
- **取りこぼしの向き**: Dragon の例のとおり、間を条件にすると、困るのは「コマンドが文字として入る」方である。文字として入った「送信して」を消す手間が要る。区切りが短い・一覧のどれかに近いのに一致しなかったときの記録（キー記録と同じく端末内）を残すと、言い方の一覧を足す材料になる。
- **数値は実機で詰める**: 600 ms・2.0 秒は資料の値からの仮の値である。Kanade の「見本の音声で測る」（9-4）に「文の途中にコマンドの言葉がある」「間を置いてコマンドを言う」の見本を足し、誤爆と取りこぼしの数を測って決め直すのがよい。

## 見つからなかったこと

- Pixel が「送信して」を文字として入れる方法と、基本のコマンドの間の秒数。
- Dragon の今の版の「コマンドの前に要る間」の既定値（公式のヘルプは設定があることだけを書く）。
- Windows の「動作するまでの待機時間」の値の公式の一覧。
- Apple Voice Control で、コマンドの言葉を書き取る前置き。
- 日本語の音声コマンドでの誤爆の報告（英語の「send」「clear」の注意書きはあるが、日本語の利用者の報告は見つからなかった）。
