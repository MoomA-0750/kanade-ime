## 2026-10-14 Windows 版の候補の窓は DLL が描く

- これまではエンジン（Java の Swing）が自分の窓に出していた。見た目を Windows 11 に合わせにくく、クリックすると入力欄からフォーカスを奪って入力中の文字が消えた（Java だけでは WS_EX_NOACTIVATE にできない）
- MS-IME と同じく、DLL がアプリのプロセスの中に Direct2D・DirectWrite で描く。角の丸め（DWM）・影・アクセントの色・カラー絵文字。エンジンは候補の一覧を命令（cands）で送るだけになり、画面を持たない
- 座標は入力欄と同じプロセスなので、拡大率に対応していないアプリでもずれない（エンジンに送っていたときは物理ピクセルに直す必要があった）
- クリック: WM_MOUSEACTIVATE で選んで MA_NOACTIVATEANDEAT を返す（クリックのメッセージを作らせない）。それでも IMM のアプリでは、システムのフックが先にクリックを見て入力中の文字を確定させる。DLL では止められないので、仕様の制限として残す
- 試してやめたこと: Compose for Desktop で候補の窓を作り直す案（本人が設定の画面を WinUI 3 に決めたのと合わせ、窓は DLL に寄せた）

## 2026-10-14 音声の途中表示を Nemotron-3.5 の逐次認識に（落としてあるとき）

- 予定にあった案B（`docs/RESEARCH-voice.md`）を作った。sherpa-onnx 1.13.8 の OnlineRecognizer で、`csukuangfj2/sherpa-onnx-nemotron-3.5-asr-streaming-0.6b-560ms-int8-2026-06-11`（約 682MB、リビジョン固定）を使う。届いた音声だけを流すので、話が長くなっても1回の計算が増えない。句読点も付く
- Nemotron は「モデル」の一覧から落とす。落としてあれば途中表示はこれ、なければ今までどおり ReazonSpeech（仮決定。戻すには一覧から Nemotron を削除する）。確定用として「適用」もできる
- 区切りは 560ms 版にした（80/160/320/1120 もある）。仮決定。速さと精度の兼ね合いは実機で見直す
- 流れの頭に 0.25 秒の無音を足す。見本の音声（いきなり話し始める）で「今日はいい天気ですね」が「キュワイ天気ですね」になり、足すと直った
- 聞き続けるモードでは、区切ったら流れを始め直す（`VoiceInput.epoch` が変わったら）
- 速さ: Pixel 3（Snapdragon 845）の4スレッドで 8.2 秒の音声に 7.6 秒（RTF 0.93）、読み込み 6.6 秒。Fold 7 は未測定。エミュレータでは入れ直した直後の読み込みが 12 秒を超え、その間は途中の文字が出なかった
- 見つけたこと（未対処）: ReazonSpeech は後ろに長い無音（31 秒）が付くと文末を落とす。押したまま長く黙ると、確定の文が欠けることがある

## 2026-11-08 音声入力: 既存の製品にならった機能

本人の依頼で既存の音声入力の仕様を調べ（`docs/research/音声入力の既存アプリの仕様.md`、コマンドの見分け方は `docs/research/音声コマンドの見分け方.md`）、本人が質問の形で選んだものを入れた（8つすべてと、まる・てん、聞き続けるモードの時間の設定）。

  - 「くてん」の聞き違いは本人の指摘（「九点」になることがほとんど）。Galaxy で Windows の音声合成の「…くてん」を parakeet にかけると「です点。」になった。認識が「く」を落とすので、文の終わりの形（です・ます・た など）の直後の「てん」「点」は「。」にした。
  - 「まる」「てん」は文の切れ目だけ（本人の選択）。後ろが文の終わり・句読点・空白のとき。1文字の「丸」「点」は前が漢字・数字なら言葉（日本丸・100点）。
- **声のコマンド**: 本人の案「それだけ言ったらコマンド、録音の中で前後に間があればコマンド」に、調べた事例（Pixel の 0.5 秒、Apple の約 0.5 秒、Dragon の間の規則、Aqua Voice の「最後に言ったときだけ送信」）を合わせた。
  - 録音を間で区切り（音の大きさを 20ms ごとに見て、雑音の床の3倍を話とする。0.6 秒以上の無音で区切る）、0.25〜2 秒の区切りだけを確定用のモデルで別に文字にする。録音の全体をまとめて文字にすると区切りが分からなくなるため。コマンドがなければ全体をふつうに文字にするので、短い区切りがある録音は認識が増える（parakeet で1回 0.1〜0.3 秒ほど）。
  - 送信・次へ・全部消す・止める は取り消せないので録音の最後の区切りだけ。Galaxy で「…テストです（間）送信して」は送信（試し打ちの欄は複数行なので改行）になり、「メッセージを送信してから寝ます」は文字のままだった。聞き続けるモードの「止めて」も止まった。
  - 書き取りたいときの逃げ道（Windows の「Type ＜語＞」のような前置き）は入れていない。文の中で言えば文字になるので、まず様子を見る。
- **直前の音声を消す**: 直後の Backspace で丸ごと消す（グライドの語と同じ。文が長いと1字ずつ消したいときに困るかもしれないので、本人に確かめる）。声の「取り消して」も同じ処理。
- **録音を捨てる**: Esc と、マイクのキーを押したまま払って離す（メッセージアプリの「横に払って取り消す」にならう）。Galaxy で両方確かめた。
- **整える前の文字**: 押している間の録音で、途中の文字（Nemotron）が確定の文（parakeet）と違えば、候補の窓に両方を出す。Galaxy で「今日はいい天気です。」と「今日は一天気です」が出て、選ぶと入れ替わった。
- **再変換・ユーザー辞書**: 表記→読みの逆引きの辞書を足した（`reverse.kdic`。Mozc の辞書から、漢字を含む表記・コスト 7000 以下・表記 8 文字以下・表記ごとに読み2つ）。全部入れると gzip で 11.7MB、コスト 8000 以下で 9.2MB、7000 以下で 5.2MB だったので 7000 にした（APK 55.8MB→61.0MB）。文の読みは、語のコスト＋区切りごとの重み 2000＋かな1字 1500 の最小で分ける（かなを安くすると「書け」を接尾の「書（しょ）」＋け と読んだ）。
  - これで、前回の未決事項だった「ほかのキーボードで入れた漢字の再変換」もできるようになった。Galaxy で音声の「協和会議があります。」を選んで Space を押すと、「協和」の文節で 共和・今日わ… から選べた。
  - ユーザー辞書を音声に当てるのは、認識が同じ読みの別の漢字で書いたときだけ効く。Galaxy で「れいや」（本人の辞書の 怜弥）は、認識が「連也」と書き、読みが違うので置き換わらなかった。
- **言いよどみ**: 規則で消す（えー・えーと・えと・えっと・あのー・うーん など）。既定は切る（整えすぎへの不満が多いという調べから）。Galaxy で「えと今日は…」の「えと」が消えた。

## 2026-11-18 Mac 版の配り方を pkg にし、Homebrew の cask でも配る

- 本人の決定。dmg に背景と Applications へのショートカットを付ける案は、作りかけで取りやめた。「開けば入る」作りでも、本人は dmg を開いてどうすればよいか迷った。pkg なら、インストーラーの案内どおりに進めるだけで入る。作りかけの差分は `.trash/2026-11-18-dmg-background-stash.patch`。
- 入れる先は全員分（`/Library/Input Methods/Kanade.app`・`/Applications/Kanade Settings.app`）。入れるときに Mac のパスワードを1回求める。pkg の postinstall は root で走るので、入力ソースへの登録（TIS は人ごと）とエンジンの配置は、ログインしている人として `launchctl asuser <uid> sudo -u <人>` で `Kanade --install` を呼ぶ。`--install` は前は登録だけだったが、エンジンを置く（syncEngine）ことも足した。
- エンジンは、これまでどおり人ごとに `~/Library/Application Support/Kanade/engine` へ写して動かす。落とした音声のモデルを engine/data に置く作りを変えずに済み、pkg の中身（root のもの）を書き換えずに済む。
- 前に本人のフォルダーへ入れた版（`~/Library/Input Methods/Kanade.app`）は、postinstall がゴミ箱へ移す。同じ bundle id の入力方式が2つあると、どちらが動くか分からなくなる。同じ理由で、pkg の BundleIsRelocatable を切る（切らないと Installer が、ほかの場所の同じ bundle id の .app を探して、そこへ入れてしまう）。
- dmg はやめ、配布物は pkg 1つにした（pkg は1つのファイルでそのまま配れ、Release・appshelf・Homebrew のどれでも同じものを使える）。開発用の tar.gz（install.sh で本人のフォルダーへ入れる。sudo が要らない）は残す。
- pkg は Xcode の pkgbuild・productbuild だけで作れる（dmgbuild や Finder の操作は要らない）。組む Mac が付ける拡張属性 com.apple.provenance は pkgbuild が `._` のファイルにして入れてしまうので、入れる前に `xattr -cr` で外す（署名は Mach-O に埋まっているので崩れない。codesign --verify で確かめた）。ssh から pkgbuild を動かすと「write: Permission denied」が4行出るが、空に近い pkg でも出るもので、中身には影響しない。
- 取り除くのは設定の画面の「設定の保存と読み込み」→「Kanade を取り除く」。全員分のものは NSAppleScript の `do shell script … with administrator privileges`（パスワードを求める。Apple Events の許可は要らない）でゴミ箱へ移し、`pkgutil --forget` で受領記録も消す。消さずにゴミ箱なので、空にするまで戻せる。設定・辞書・音声のモデルを残すか選べる（残すと入れ直したときにそのまま使える）。
- Homebrew は自分用の tap（`MoomA-0750/homebrew-tap`、cask `kanade`）。kanade-ime は公開のリポジトリなので、pkg は Release（タグ `mac-v<版>`）に付け、cask はそこを指す。版は 年.月.日.時分（エンジンの VERSION から）。`brew uninstall` は入力ソースを無効にしてから pkgutil の記録で外し、`--zap` で設定と記録も消す。
- 署名なしの pkg: ダウンロードしたもの（隔離の印つき）は、開くと Gatekeeper に止められ（`spctl -t install` が「no usable signature」で rejected）、システム設定 → プライバシーとセキュリティの「このまま開く」が要る。Homebrew 5 から `--no-quarantine` が無くなり、7 はどの tap のダウンロードにも隔離の印を付けると報告されている。pkg を `installer` に渡すときに止められるかは、Homebrew の入った Mac で確かめていない。どちらも Developer ID Installer の署名と公証で解ける。

## 2026-11-21 聞き続けるモードを PC の版（Windows・Linux・macOS）に入れる

- 本人の要望「全てのプラットフォームで機能をなるべく揃えたい」。設計は design-planner の案（`docs/CONTINUOUS-PC.md`。比べた案と推す理由はそちら）。夜間の自走で、推す案で仮決定して作った。

- 区切りの結果は通し番号で話した順にそろえ、Esc・入力欄の移動で終えたら回の番号を進めて遅れた結果を捨てる。Kanade で打っている途中に届いた文は、打った文字が確定してから入れる（今の長押しの `commitAll` のように打っている途中を勝手に確定させると、何度も入る聞き続けるモードでは打つたびに切られるため）。
