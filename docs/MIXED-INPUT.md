# 日英の切り替え不要（Meltype のような入力）の設計メモ

2026-11-23。調査と設計だけ（実装なし）。SPEC.md への項目追加は、本人が方針を決めてから。仕様の正本は SPEC.md。

## 1. Meltype の仕組み（公開文書から。ソースは読んでいない）

- yksr-melt/Meltype。GPL-3.0-or-later、C# (.NET 10)。記事 https://kai-you.net/article/96794 （2026-10-09）、README・docs（USAGE・WINDOWS・LINUX・MACOS・dev/DEVELOPMENT・THIRD-PARTY-NOTICES）。
- 変換は Mozc（BSD-3 の同梱ヘルパー）と Zenzai（llama.cpp + zenz-v3.2-small、Apache-2.0）の `HybridConverter`。Zenzai が使えなければ Mozc。Zenzai はキャレット前の文を文脈にする。
- 日英の判定は `Detection/`（`CompositionDetector`）。辞書ベース（英単語・日本語の読み・カタカナ語・外来語・分野辞書）。確率モデルの記述は文書に無い。**判定の単位・しきい値・誤判定の学習の中身は文書では不明**（記事は「強さを調整可能」「直すと次から反映」と書く）。
- UX: 誤判定は 半角/全角 で日英を入れ替え、直した語を覚える。確定後も続きを打って直ることがある。英単語で終わる文は Space が普通の空白で、変換は Shift+Space。`/` `$` `@` 始まりはそのまま。「英字を主に入力」。アプリ別（一般・コード・ゲーム・OFF。コードはコメント・文字列内だけ日本語判定）。
- 品質: 約 550 例の混在ベンチ、誤判定報告の回帰テスト（逆向き・似た入力も足す）。
- IME 版（TSF、下線付きで入力欄に入る）とキーボード版（変換ボックス、Enter まで入力欄に入らない）。判定・変換・キーは同じ。Mac・Linux はプレビュー（Swift の IMK、IBus・fcitx5。判定は NativeAOT の C ライブラリ）。
- 辞書データに JMdict・SCOWL・SKK・Sudachi など（CC BY-SA・GPL-2.0+ など）を含み、全体が GPL-3.0。Mozc-UT は同梱しない。

## 2. ライセンスの整理（一般論。法的な助言ではない）

- Kanade は MIT。GPL-3.0 のコードを入れると、配る物全体が GPL-3.0 の条件（ソース公開・同じ許諾）になる。MIT のままにするなら入れられない。C# から Kotlin へ書き直しても派生物になりうる。Meltype の評価セット・データも同様に取り込まない。
- 仕組みの理解（公開文書に書いてある動き）にとどめ、ソースは読まない（クリーンルーム）。英単語の一覧は Meltype を通さず、Kanade がすでに使う FrequencyWords・JMdict（どちらも CC BY-SA 4.0、docs/THIRD-PARTY.md）と SCOWL から直接作り、別ファイルの CC BY-SA データとして出典を示す。コードの MIT には影響させない。

## 3. 推す案: B1「判定してから変換する」（自前・Meltype のコードは見ない）

| | A 流用 | **B1 判定→変換（推す）** | B2 ラティスで日英を一緒に解く | C 候補に混ぜるだけ |
|---|---|---|---|---|
| ライセンス | GPL 化 | 問題なし | 問題なし | 問題なし |
| 変える場所 | 多い（言語違い） | 新 5・既存 15 前後 | B1 より深い | 2〜3 |
| 戻しやすさ | 難 | 設定オフで今のまま | 変換の中心を作り替える | 容易 |
| 要望を満たすか | ○ | ○ | ○ | ×（ライブ変換の1位が「ぎてゅb」のまま） |

B2 は B1 で区切りのずれが多いと分かったときの次の手。C の一部は P0 として先に入れる。直接入力（2-1）は残し、日英混在は「日本語モードの中の機能」にする。

### 骨組み
- core の純粋な関数 `MixedSegmenter`。入力は打ったキー（`KanaUnit.raw` の並び）と左の文脈、出力は区間ごとの英／日と強さ。辞書を引くだけで zenz は使わない。
- 英語と決めた区間は 1 つの `KanaUnit`（表記＝打った英字、英語の印付き）にまとめ、ラティスには区間をまたぐ「英語の語」のノードを 1 つ置く（今は辞書に無い ASCII が 1 文字ごと 12000 の未知語ノードになる。`KanaKanjiConverter.kt` 76–81 行）。
- zenz は英語の区間を動かさない（4-11 と同じ。食い違いの位置が英語の区間の中なら合格扱い）。

### 判定の単位と材料
単位は打った英字の並びの中の「語」。境目は `KanaUnit` の境目にそろえる。

| 材料 | 判定 | zenz |
|---|---|---|
| ローマ字として成り立たない（子音が余る: git・push） | 英語（強）。英単語一覧にも無ければ今のまま | 不要 |
| 大文字始まり、`/` `$` `@` 始まり、`.` `_` 数字を含む | 英語（強） | 不要 |
| ローマ字として成り立ち、英単語一覧に無い | 日本語 | 不要 |
| 英単語一覧にあり、日本語の読みとしてラティスのコストが高い | 英語 | 不要 |
| どちらも自然（made／まで、dame／だめ、name、take、note、game、home） | 学習 → 前後が英語か → zenz | 要る（P3） |
| 2 文字の語（to・no・so・do・go・me・he・a） | 英語が並ぶ中でだけ英語、ほかは日本語 | 不要 |

- 学習: 小文字の綴りごとに英／日と回数。入れ替えて直した語は強く、直さず確定した語は弱く。端末の中だけ。入力の記録の `direct` からは自動で学ばない（記録は任意・既定オフで、学習と混ぜない）。
- ちらつき抑え: 決め直すのは末尾の区間だけ。前の区間は後ろに 1 語打ったら固める。いったん英語と見た語は区切り（空白・句読点・日本語として成り立つ続き）まで英語のまま。迷う語は、zenz の結果が来るまで打った英字を出す。
- 速さ: 判定は辞書引きだけ。zenz は「迷う」行のときだけ、2 文を `score` で比べる（見込み 2〜5ms／回、未計測）。

## 4. 誤判定のとき（キーで戻す）

Meltype の 半角/全角 だけでは足りない: Linux は fcitx5 が 半角/全角・Ctrl+Space を取って Kanade まで届かず（SPEC 11-2）、US 配列にはキーが無い。Tab（予測・補完、3-5）と Shift+Space（前の候補、4-3）は使用済み。

- 入力中: 切り替えのキー（2-1・2-2）で末尾（またはカーソルの所）の区間の日英を入れ替え（今は確定してから切り替えるのが、入力中だけ区間の入れ替えに変わる）。混在中は F6/F10 と Ctrl の同じ役のキーも区間に効かせる（Linux はこちらだけ）。
- 確定後: 直後（ほかのキーの前・3 秒以内）の F6/F10 で最後の区間を入れ替える。既存の `fix`（直後 5 秒以内の Backspace、13-3）の記録と整合させる。
- 入れ替えた語は学習する（強く）。

## 5. 入力経路ごと

| 経路 | 扱い |
|---|---|
| 物理キー | 全部に効く（本体） |
| 画面の QWERTY（`soft`） | 同じ経路なのでそのまま |
| テンキー（フリック） | ローマ字を通らないので判定しない。英語は 4-6（カタカナ→英語）の候補 |
| グライド | P6。日本語のなぞりの候補に英単語の候補も混ぜる |
| 音声 | P6。今は変えない案（parakeet-ja が英語をカタカナで書くか英字で書くかは未確認） |
| パスワード欄 | 1-4 のとおり手を出さない |
| ターミナル（Termux、`input_log_limited_apps`） | 既定でオフ |
| 絵文字の入り口に `/` `@` を選んだとき | 絵文字（6-5）を先に |

アプリ別の「コード」モード（コメント・文字列内だけ日本語）は、入力欄の中身の文法を取る手段が版ごとにまちまちで確かめられないため後回し。

## 7. 評価

- `eval/mixed.tsv`（打ったキー<TAB>正解、`|` で複数）。まず 300 文、のち 600 文。分類: 技術の語・ローマ字としても成り立つ英語・ローマ字に見える日本語・英語だけの文・コードっぽい語と URL・大文字・2 文字の語。日本語だけの文は daily・daily2 を流用（日本語を英語と誤る率の分母）。Meltype の評価セットは使わない。
- 指標: 語ごとの誤判定率（日→英・英→日を分ける）／文が丸ごと合う割合／ちらつきの数（キーを 1 つずつ流し、出した区間が変わった回数）／1 キーあたりの時間（zenz なし・あり、中央値と 95 パーセンタイル）／zenz を呼んだ割合。
- 実データ: 入力の記録の `switch` の `before` → `direct` の語 → 次の `commit` は、本人が自分で英語に切り替えた所で、正解の分かる混在例になる。P4 の後は `flip` が誤判定の回帰例。外へは出さない。
- SPEC の「確定」: `MixedInputTest`（zenz なしで決まる動き）を付けたものから確定。zenz に頼る部分は「仮」で、`eval-mixed` の数を decisions に残す。

## 10. 本人に決めてほしい点（★は推し）

1. 方式: ★B（B1 から）／A（GPL 化を受け入れる）／C だけ
2. 既定: ★オフ（評価の目標を満たしたら決め直す）／オン／新しく入れた人だけオン
3. 位置づけ: ★日本語モードの中の機能（直接入力は残す）／切り替えそのものを無くす
4. 直すキー: ★(a) 入力中は切り替えキーで末尾の区間を入れ替え＋(b) 混在中は F6/F10・Ctrl の同じ役のキーも区間に効かせる（Linux は b のみ）／(c) 新しいキーを決める
5. Space: ★英語で終わるときは空白（英語だけなら空白ごと確定、変換は ↓・Shift+Space）／いつも変換／Meltype と同じ
6. Shift＋英字: ★英語の語を始める（強い印）／今のまま全角
7. 2 文字の英単語: ★英語が並ぶ中でだけ英語／いつも日本語／学習で決める
8. 確定後の直し: ★直後の F6/F10／直後の切り替えキー（モード替えと重なる）／作らない
9. 学習の範囲: ★端末の中だけ（書き出しに入れない）／書き出しに入れる／入力の記録からも学ぶ
10. アプリ別: ★オン・オフ・英字を主にの 3 つ（ターミナルは既定オフ）／Meltype と同じ 4 つ／作らない
11. 英字を主に入力: ★アプリ別の「英字を主に」で兼ねる／別のスイッチ／作らない
12. 評価の目標: ★daily 系の正解数が下がらない・日本語を英語と誤る 1% 以下・英語を日本語と誤る 5% 以下・判定 1 キー 1ms 以下／本人が数を決める
13. 実データの評価セットの置き場: ★リポジトリの外（Vault か gitignore したフォルダー）／commit する
14. 音声: ★今は変えない／カタカナ→英語の表（4-6）を学習した英語の語だけに使う
